# gh-yog

A GitHub CLI extension that builds a review brief for a pull request: what
changed, what is risky, what is untested, and where to start reading.

Plain code computes the facts. An AI agent of your choice writes the
judgment. `gh yog check` recomputes the facts from git and refuses any brief
that leaves a change unassigned, ranks a hard-flagged change below high, or
cites lines that are not in the diff. Nothing is written to GitHub.

Named for Yog-Sothoth, the gate and the key, and the guardian of the gate.

## Install

```bash
gh extension install ElijahKotyluk/gh-yog
gh extension upgrade yog    # later
```

Requires `gh` signed in (`gh auth status`), `git`, and `python3` 3.8 or
newer. macOS and Linux; Windows is untested.

To have an AI agent write the brief, use the
[yog skill](https://github.com/ElijahKotyluk/yog). It carries its own copy of
this CLI, so neither needs the other.

## Without an agent

`gh yog facts` is useful on its own: a computed risk map of a PR with no AI
involved.

```bash
gh yog collect 1670                 # fetch the PR, compute facts, write a brief template
gh yog facts FACTS                  # hard flags, files, test pairing, dependencies
gh yog hunks FACTS 3 7.2            # read units of the diff with line numbers
gh yog show FACTS src/app.ts --lines 40-80
```

## The brief workflow

```bash
gh yog collect [PR]          # facts.json + brief.json (template) in .git/yog/
# an agent fills brief.json
gh yog check BRIEF [PR]      # recompute facts, validate the brief against that PR
gh yog render BRIEF [PR]     # check, then print it; -f md for markdown
```

`collect` fetches the PR's head and base into `refs/yog/...` from the PR's
base repository. It never creates a branch, checks anything out, or touches
the working tree. The diff is from the merge base to the head, which is what
GitHub shows.

`check` and `render` take the PR (or `--base REF` for local commits) from the
command line, defaulting to the current branch's PR, and refuse a brief
written for anything else. The brief never chooses what gets checked.

## What the CLI computes

- **Units.** Every changed file gets a unit `F.0`; every hunk `F.H`; hunks
  over 80 lines are split into chunks `F.H.C`. Every unit of a file that is
  not mechanical must go into exactly one group, or into "not examined".
- **Mechanical files.** Lockfiles, files marked generated by the base
  branch's `.gitattributes` or `.github/yog.json`, files whose base version
  carries a generator header (`@generated`, `Code generated ... DO NOT
  EDIT`) and are edited in place, and pure renames of docs
  and assets. Nothing the PR itself adds can make a file mechanical, renames
  of code never are, and any flag makes a file ordinary again. Lockfiles yog
  cannot parse (anything but npm, pnpm and yarn v1) are never mechanical.
- **Hard flags**, which force their group to high risk:

  | flag | fires on |
  | --- | --- |
  | `ci` | CI or build configuration changed, or moved out of CI |
  | `local-exec` | config that runs code on developer machines (git hooks, devcontainer, editor tasks, `.envrc`, `.pth`) |
  | `registry-config` | registry configuration, or a dependency from git, a URL or an index URL |
  | `install-script` | package install scripts changed |
  | `lockfile-integrity` | checksum or source changed at the same version |
  | `lockfile-source` | a package resolved from outside the registry |
  | `lockfile-identity` | an entry that resolves to a different package than its name |
  | `lockfile-unexplained` | new packages with no manifest change |
  | `lockfile-unaccounted` | a lockfile that does not parse, changes no entry, or is deleted |
  | `dep-install-script` | a new dependency that runs an install script |
  | `review-surface` | `.gitattributes`, CODEOWNERS, `.gitmodules` or yog config changed |
  | `policy-sensitive` | a path the base branch's `.github/yog.json` marks sensitive |
  | `sensitive-rename` | a rename into an execution path, or a rename that turns a file into code |
  | `binary` | a binary that is not an image, font, media or PDF |
  | `test-deleted` | a test deleted or renamed out of test naming |
  | `test-skip` | a test skipped, focused or marked expected to fail |
  | `suppression` | a lint, type or coverage check suppressed |
  | `hidden-text` | invisible, bidi or control characters in a line or file name |
  | `mixed-script` | an identifier mixing Latin with look-alike letters |
  | `exec-bit` | executable bit changed, or a new executable |
  | `symlink` | a symlink added or changed |
  | `submodule` | a submodule changed (its content is not reviewed) |

- **Hints**, shown next to the group but setting no minimum:
  `sensitive-keyword`, `dangerous-call`, `migration`, `ai-addressed` (text
  that addresses AI tools or reviewers), `homoglyph`, `claims-generated` (a
  new file that says it is generated), `long-line`, `assertions-removed`,
  `dependency`, `sensitive-path` (a path that runs or loads code),
  `lockfile-unparsed` (a lockfile format yog does not read), and
  `lockfile-new-packages` (new packages alongside a manifest change).
- **Test pairing**, a heuristic: does a test file named like the source file
  (or its folder) exist, and did this PR change it.
- **Claims**: the PR title, each sentence or bullet of its description, and
  each commit subject. The brief must answer every one.

Diffs run with every git setting that changes their output pinned, and with
`.gitattributes` diff drivers and textconv ignored, so local config cannot
hide a change.

## Repo policy

`.github/yog.json` on the base branch can add globs:

```json
{
  "sensitive": ["infra/", "/deploy/**"],
  "generated": ["src/gen/**"],
  "registries": ["https://npm.corp.example/"]
}
```

- `sensitive`: any change under these paths is a hard flag.
- `generated`: files here are mechanical. A rename counts only when both
  paths are covered and the content is unchanged.
- `registries`: extra package registries that lockfile sources may use
  besides the public npm and yarn registries.

A leading `/` anchors at the root. A trailing `/` means a folder, at any
depth unless anchored. A bare name matches that file or folder anywhere. It is read from the base branch only, so a PR cannot
switch off its own flags, and a PR that changes it gets a hard flag. Globs
that match nothing on the base branch are reported by `collect`.

## What it cannot enforce

- `check` proves every unit was assigned to a group, not that the agent read
  or understood it.
- The agent's text can describe a hard-flagged change as harmless. The flag
  still shows next to it, but the framing can mislead.
- The skill's rules (no checkout, no running PR code, no posting) are
  instructions to the agent. An agent with a shell can break them, and
  prompt injection in the diff can push it to.
- Heuristic flags have false positives and false negatives.
- A dependency range change in a manifest can legitimately pull in new
  packages, so new lockfile packages next to one are a hint, not a hard
  flag. Read them.
- Submodule content and dependency code outside the lockfile are not
  reviewed. pnpm 9 lockfiles do not record install scripts, so
  `dep-install-script` cannot fire for them.
- Local mode (`--base/--head`) exists for testing yog. The agent that
  wrote a change cannot review it independently.

## Compatibility

`facts.json` and `brief.json` carry schema numbers, currently 1. A change
that breaks either bumps that number and the minor version.

This repo is the source of truth for the CLI. The yog skill bundles
byte-identical copies of `gh-yog` and `tests/test_yog.py`; after a change
here, run `scripts/sync-cli` in the yog repo.

## Development

```bash
python3 -m unittest discover -s tests
gh extension install .    # from a checkout named gh-yog: run your working copy as gh yog
```

No dependencies. Tests build fixture repositories with git in temp dirs and
never reach GitHub.
